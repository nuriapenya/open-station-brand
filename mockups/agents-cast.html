OpenStation · Agents · design proposal

Agents, as a cast

We ship five good agents and show them as five identical grey robots in a sidebar. This proposes giving them faces and voices, and turning "create an agent" into casting one.

Prompted by berd, where an agent carries a face, a "good for" and a "vibes" line. The faces here are not new art: they are Mio, which is already a full character system in src/mio/.

Today

Five agents, one face

pre_get_avatar_data forces the same robot SVG onto every agent, everywhere, including the Users list in wp-admin. The data model has no avatar field at all.

tl;dr, Comment Concierge, Localizer, SEO Medic, Alt Text Librarian. You cannot tell which is which.

Proposed

The crew

The same five agents, unchanged in what they do. Each carries a silhouette, a hue, and one line of voice. The card grid replaces the 260px sidebar, so the agents that came with the station finally look like a crew.

Design notes

One new field, not two

berd carries both good_for and vibes. We only need vibes: our existing description ("When to use") already does the good_for job, and the five defaults are already written that way. What we have no field for is voice.

Vibes is not decoration. It goes into the system prompt, which is why it needs a strict sanitizer and a hard length cap: it is untrusted text reaching a model.

The mesh budget gets one scoped exception

The kit-wide rule is that selected means flat accent and the mesh is spent on hero moments only. Agent identity is the exception, and only agent identity: a cast has to be distinguishable, so the faces get to glow. Everything else here obeys the rule, and the flow still spends exactly one holo moment, on "Draft it for me".

Powers, not Refine

PR #603 called step 2 "Refine", which describes what you do to a form rather than what you are deciding. What you are actually deciding is what this thing is allowed to touch. Naming the step Powers keeps the security model in the flow instead of underneath it, and it reads as the fun part rather than the paperwork.

Faces do not need PixiJS, but they do need two renderers

Only src/mio/mio.ts and src/mio/render.ts import Pixi. shapeProfile() and chromaRing() are pure, so a still face is a path, a ring ramp and two eye pills, which the my-wordpress bundle can render on its own. The silhouettes on this page were generated exactly that way.

PHP needs its own copy anyway, because pre_get_avatar_data fires on the front end for comment authors with no shell bundle on the page. Two renderers, one committed golden fixture that both are tested against, which is the pattern mio-defaults-parity.test.ts already uses for the PHP and TS copies of the defaults.

The generated SVG carries no text and no user-supplied string: numbers and fixed element names only. That is a hard rule, not a preference, because the files are served from uploads.

A cast, not a catalogue

Nine shapes crossed with a free hue, span, saturation, glow, outline and eye size is an open space, not a grid of options. The picker never shows "all the faces": it shows twelve candidates rolled from a seed, with a shuffle for twelve more. <os-swatch-grid> and <os-swatch> already do this, radiogroup semantics included, so no new component is needed.

Whether every shape belongs to agents is a real question. A heart reads as a joke on something that edits your posts.

The five defaults do not exist until you turn Agents on

defaults.php only loads inside the flag, so a site that has never enabled Agents has none, and today's off-state is a wall of explanatory text. The cast should be what that state shows: the same five cards, greyed and inert, above the "Turn on Agents" button. Seeing who you would get is a better argument than a paragraph about it.

That needs the definitions split out of defaults.php into a pure data file, because the current file registers its seeder at file scope and would fatal if loaded with the flag off.

Steps are not clickable, and Expert is untouched

The step trail is a position indicator, not navigation: Back is the way back. And Expert is still one segment away, which is the two-door shape this flow was asked to keep. Nothing in the existing form changes.

What existing installs see

Agents with no stored face fall back to today's robot, so nothing breaks. The five defaults get faces in the same change that ships the field, so an existing site gains a crew rather than five blanks.

The two doors, and an argument against them

Guided and Expert are kept because that is what was asked for. The honest counter-argument, worth having out loud: a redesign whose whole premise is "agents are a cast" ships a segment labelled "skip the cast". The alternative is folding Expert into a disclosure on this flow that reveals the raw instructions field, which is already there. Not changing it unilaterally.

Still open

Whether the section keeps the name "Agents" or leans into "crew" in the copy. Whether a face is rerollable after creation or fixed at birth. Whether vibes belongs on the roster card at all, since the tile already carries five things.

Resolved on the way here: rateLimit surfaces (it works, it is in the REST shape, it is one number field), model does not (the runner ignores it until Core exposes model selection, and a control that does nothing is worse than no control).
